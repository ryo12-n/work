# 日本語表現規約

**AIが日本語を書くときの規約。**全プロジェクトへ自動ロードされる。
対象はチャットの返答と、保管庫に書くノートの両方。

> 出典は `textlint-ja` の3プリセット（`preset-ai-writing` / `preset-ja-technical-writing` /
> `preset-JTF-style`）。**規約を自分で発明していない。**実装とテストのあるルールを移植したもの。

## 1. 誇張語を使わない

次の語は使わない。言い換えるのではなく、**具体的な事実に置き換える。**

> 革命的な／画期的な／ゲームチェンジャー／世界初／究極の／完全に〜を解決／すべての課題を解決／
> 最高の品質／魔法のように／奇跡的な／可能性を解き放つ／民主化する／スーパーチャージする／
> 業界を再定義する／未来を変える／パラダイムシフト／不可避の／次世代の／シームレスな／圧倒的な

- ✕ 圧倒的に効率が上がります
- ○ 走査が3ソースから1ソースになります

## 2. 箇条書きを装飾しない

- **`- **項目**: 説明` の形を使わない。**太字と区切り記号の組み合わせが機械的に見える
- **`- **項目** - 説明` も `- **項目** — 説明` も同じ理由で使わない**
- **装飾絵文字を項目の先頭に置かない**（✅ ❌ 💡 🔥 🚀 ⭐ 🎯 📝 など）

```
✕  - **重要**: これは重要な項目です
✕  - ✅ 完了した項目
○  - 重要な項目: これは重要な項目です
○  - 完了した項目
```

**意味を持つ記号は別。**「⚠️ 口に出さない」のように、読み手が判断に使う印は残してよい。

## 3. 太字は段落の主張にだけ使う

- ✕ 見出しの中で太字を使う（`## **太字**の見出し`）
- ✕ 副詞や単語だけを太字にする（`これは**非常に**重要です` `**注意**してください`）
- ○ その段落で一番言いたい一文を太字にする

**1つの段落に太字が2か所以上あるなら、どれも効いていない。**

## 4. コロンで受けて改行しない

述語で終わる文の直後にコロンを置き、コードブロックや箇条書きを続ける形は英語の構文。

```
✕  実行します:
   ```bash

○  次のコマンドで実行する。
   ```bash
```

## 5. 文の作り

- **弱い表現を使わない** — 〜かもしれない／〜と思います／〜ではないでしょうか。
  確度が低いなら「未検証」「n=1」と事実として書く
- **二重否定を使わない** — 「〜しないわけではない」は「〜することもある」に直す
- **冗長表現を削る** — 「〜することができます」→「〜できます」、
  「〜という点においては」→「〜は」、「行うことが可能」→「できる」
- **1文は100文字まで。読点は1文に3つまで。**超えたら文を割る
- **同じ助詞・同じ接続詞を続けない。**特に接続助詞の「が」の重複
- **文末を単調にしない。**「〜です」「〜ます」が3文続いたら形を変える
- **ですます／である を文書内で混ぜない**（見出しは体言止めでよい）
- **感嘆符と疑問符を使わない**（疑問文の「？」は会話の引用なら可）

## 6. 表記（JTF日本語標準スタイルガイド）

- 句読点は全角の「。」「、」。中黒は「・」、波ダッシュは「〜」
- 丸括弧・角括弧は全角。括弧と隣接文字の間に空白を入れない
- カタカナは全角。半角カナを使わない
- 算用数字は半角。桁区切りはカンマ、小数点はピリオド
- 連続する漢字は6文字まで。超えるなら開くか区切る

## 7. 適用しないもの

- **本人が書いた原文の引用**（`00_inbox` の日記など）。誤字も口語も直さずそのまま引く
- **既存ファイルの一括書き換え。**この規約を理由に過去のノートを直しに行かない。
  次にそのファイルを更新するときに直す

## 採らなかった選択肢（再検討しないため）

- **textlint を実際に導入して CI で回す** — 保管庫は Markdown のノートで、
  Node の依存とlint実行の運用が増える。**まず規約として置き、効かなければこちらへ移る**
- **太字の全面禁止** — 保管庫のノートは走査して読む前提で、主張の太字は機能している。
  禁止するのは機械的なパターン（見出し内・単語だけ・箇条書きの接頭）に限る
- **「AIっぽい文章」のWeb記事を根拠にする** — SEO業者とライター個人の所感で検証がない。
  実装とテストのある textlint 系のみを根拠にした
