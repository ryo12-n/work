`C:\Users\nr202\projects\work` の使い終わったワークツリーを片付ける。

**このタスクが要る理由。** ワークツリーの中で動いているセッションは、自分の作業ディレクトリを
削除できない（Windows がプロセスの cwd をロックする）。作業を終えたセッションは
ブランチのマージまではできても、ディレクトリを消しきれずに空の殻を残す。
**その殻を、そこで動いていない別セッションが引き取る。**

## 完全自律で走る

**人の承認を待たない。**承認のゲートは fable のサブエージェントによるレビューが兼ねる。
判断が要るものは削除せず報告に回すため、待つ必要がない。

## 消してよいものの条件

**4つすべてを満たすときだけ削除する。1つでも欠けたら報告に回す。**

- `C:\Users\nr202\projects\work\.claude\worktrees\` の直下にある
- 未コミットの変更と未追跡ファイルが1件も無い
- ブランチが `main` にマージ済み
- 自分（このタスク）の作業ディレクトリではない

**本体チェックアウト `C:\Users\nr202\projects\work` は絶対に削除しない。**
`git worktree list` の先頭行は常に本体で、これは対象外である。

## 手順

### 0. 着手前レビュー

削除候補と、各候補が上の4条件をどう満たすかを列挙し、fable のサブエージェントへ
レビューを依頼する。Agent ツールを `model: "fable"` で呼ぶ（使えない場合は `"opus"`）。

**候補がゼロなら、レビューを飛ばして第4節の報告へ進む。**

レビューで却下された候補は削除しない。却下理由を報告に載せる。

### 1. 列挙

**Bash ツールを使う**（PowerShell ではない）。最初に本体チェックアウトへ移動する。
ワークツリーの中から実行すると、自分で自分を消しにいく。

```bash
cd "C:/Users/nr202/projects/work" && git worktree list --porcelain
```

```bash
cd "C:/Users/nr202/projects/work" && ls -1 ".claude/worktrees/" 2>/dev/null
```

2つの出力を突き合わせると、ワークツリーは3種類に分かれる。

- **登録あり** — `git worktree list` に出る。第2節で判定する
- **登録なしで空** — ディレクトリだけが残った殻。第3節で消す
- **登録なしで中身あり** — git が知らない実体。**消さずに報告する**

### 2. 登録ありのワークツリーを判定する

各ワークツリー `<path>` について、次の2つを取る。

```bash
cd "C:/Users/nr202/projects/work" && git -C "<path>" status --porcelain -uall
```

```bash
cd "C:/Users/nr202/projects/work" && git -C "<path>" rev-parse --abbrev-ref HEAD
```

`status` の出力が空でなければ、**そのワークツリーにしか無いファイルがある。**削除せず、
ファイル名を報告する。

ブランチ名 `<branch>` が取れたら、マージ済みかを確認する。

```bash
cd "C:/Users/nr202/projects/work" && git branch --merged main --format='%(refname:short)'
```

この一覧に `<branch>` が無ければ未マージである。削除せず報告する。
`detached HEAD` の場合も削除せず報告する。**外部が管理している作業場の可能性がある。**

条件を満たしたものだけを削除する。

```bash
cd "C:/Users/nr202/projects/work" && git worktree remove "<path>" && git worktree prune && git branch -d "<branch>"
```

`git worktree remove` が `Permission denied` で落ちたら、**そのワークツリーで別のセッションが
動いている。**削除せずに報告し、翌日また試す。

### 3. 登録なしの空ディレクトリを消す

`rmdir` を使う。**`rm -rf` を使わない。**`rmdir` は中身があると失敗するため、
判定を誤っても中身のあるディレクトリを壊さない。これが安全弁になっている。

```bash
cd "C:/Users/nr202/projects/work" && rmdir ".claude/worktrees/<name>"
```

失敗したら中身がある。消さずに報告する。

`.claude/worktrees/` 自体が空になっても、そのディレクトリは残してよい。

### 4. 完了後レビューと報告

削除したものと報告に回したものを整理し、fable のサブエージェントへ完了レビューを依頼する。
**1件も削除していない場合はレビューを省く。**

報告は簡潔に。前置き・要約・励ましを書かない。

- 対象ゼロなら「ワークツリーなし」の1行で終える
- 削除も報告もゼロなら「異常なし（N件確認）」の1行
- それ以外は、**削除したもの**と**判断が要るもの**を分けて箇条書きにする

## やらないこと

- **`git worktree remove --force` を使わない。**拒否は「そこに何かある」という情報である
- **`git branch -D` を使わない。**`-d` が拒否するブランチは未マージのコミットを持つ
- **ワークツリーを新しく作らない。**このタスクは片付けだけを持つ
- **本体チェックアウトの作業ツリーに触れない。**`main` のファイルを直さない
