メモリが規約に沿って保たれているかを点検し、**人の承認を待たずに是正する。**

**点検対象はリポジトリの原本（`C:\Users\nr202\projects\work\harness\`）である。**
`~/.claude` は配布物であり、直接直しても次のデプロイで巻き戻る。
直したら `bash "C:/Users/nr202/projects/work/scripts/deploy.sh" --yes` まで実行すること。

**このファイルに判定基準を書かない。** ここは駆動だけを持つ。

## 手順

1. **基準を読む。この2本が正。**

   - `C:\Users\nr202\projects\work\harness\rules\メモリ管理規約.md` — 本文1〜11条。**何が正しいか**
   - `C:\Users\nr202\projects\work\harness\scheduled-tasks\memory-health-check\reference\点検項目.md` —
     0〜7節。**何を検査し、どこまで自律で直すか**

   前者はユーザースコープで自動ロードされているが、**必ず読み直す。**本人が編集している。
   **どちらにも書かれていない基準を勝手に足さない。**
   読めなかった場合は点検を実行せず、「基準が読めないため中止」とだけ報告して終了する。

2. **点検対象を列挙する**（点検項目1節）。対象外を点検も修復もしない。
   **索引のパスを信用せず、`ls` / `find` で実体を確認してから判定する。**
   対象が1件も無ければ「メモリなし。点検不要」と報告して終了する。

3. **各ファイルを読み、A表・B表（点検項目2・3節）に照らす。**

4. **A表に該当したら、その場で直す。** レビュー不要。
   ただし**復元手順を1行で書けないものは実行せず報告へ回す**（点検項目0節）。
   索引の修復は先に自動修復スクリプトを試す。**衝突コピー（`〜 2.md`）があるときは使わない。**

   ```bash
   bash "C:/Users/nr202/.claude/scheduled-tasks/config-health-check/fix-index.sh" --apply
   ```

5. **B表のうち「自律」の項目は、修復案を作りサブエージェントのレビューに掛ける。**
   依頼のしかたは点検項目5節に従う。要点：

   - レビュアの指定は `C:\Users\nr202\projects\work\harness\CLAUDE.md` の規定に従う
   - **渡すのは unified diff と規約の該当条項だけ。「なぜ直すか」を渡さない**
   - 問いは「**この修復で失われる情報は何か**」
   - 出力形式は **判定 / 失われる情報 / 復元手順**
   - **レビューが復元手順を書けなかったものは実行しない**

   通ったものだけ適用する。**却下されたものと理由を実行ログに残す。**

6. **B表のうち「報告のみ」の項目（B4/B5/B6/B9 と `30_context/` 絡みの B8）は直さない。**

7. **安全弁を守る**（点検項目4節）。結論を持つノートは1周3ファイルまで、
   削除・改名・統合は1周0件、**累計削除20行を超えたら以降は全件報告へ切り替える。**

8. **実行ログを更新する。**
   `C:\Users\nr202\.claude\scheduled-tasks\memory-health-check\実行ログ.md` へ**上書き**。
   保管庫の作業ログへ書かない（設計記録を消すため）。
   **安全弁のカウンタ（点検項目6節）は現在値として必ず更新する。**
   カウンタが発火したら、その旨を報告の先頭に置く。

## 報告

**形式は点検項目7節に従う。** ここに重複して書かない。
